# RL Token(RLT)による SmolVLA の改善実験 — LIBERO-10 Task 0

凍結した SmolVLA(`lerobot/smolvla_libero`)の上に、RL token と小さな actor-critic を載せ、LIBERO-10 の Task 0
("put both the alphabet soup and the tomato sauce in the basket")の成功率を上げる実験の記録。
実験期間は 2026-10-01〜10-04。この文書は、実験の目的、実装、データ、各実験の設定と結果、発生した問題、考察、再現手順をまとめる。
**最後に、ベースモデルと最良の結果の比較表を載せている。**

---

## 0. 要旨

- **最良の構成(H):** 1 つ目の物体を掴む局面は、RL で学習した actor(G)を固定して使い、2 つ目の物体を掴む局面は、専用に学習した actor で行う。
  VLA(SmolVLA)は常に凍結。
- **成功率(50 の固定初期状態を 1 回ずつ):** ベース 0.40(最初の実験)/ 0.46(同じコード経路で再評価)→ H は 0.74(最良の評価)。
  評価シードを変えた 3 回は 0.74 / 0.70 / 0.70(平均 0.713)。標準誤差は約 0.07。
- **改善の大部分は、1 つ目の把持の改善による。** 1 つ目の物体を保持できる割合は、ベース 60% → H 93〜96%。
  ベースの失敗の 74% は「1 つ目を掴めない」だった。
- **2 つ目の局面の改善は小さい。** 1 つ目を保持した後に 2 つ目も保持できる割合は、ベース 77% → H 81%(3 回の合計)。
  1 つの actor を 2 つの局面で共有して学習した場合(F、G)は、むしろ悪化した(0.63、0.65)。
  2 つ目の局面に専用の actor を作り、VLA 相当の初期値から学習することで、初めてベースを上回った。
- 空振り(何も掴めずに閉じる)への罰(−0.2)は、効果が確認できなかった(I)。
- **ベースの成功率は、評価シードを変えた 5 回の平均で 0.428**(0.34〜0.48)。単一の評価の 0.46 は、高めの回だった(6.10 節)。H の 3 回の平均 0.713 との差は +0.29。
- **DSRL(初期ノイズを操作する SAC)の SmolVLA 版は、RLT に届かなかった**(成功率 0.42 / 0.52、1 つ目の保持 72%)。時間オフセットを報酬に足す方法(E2b)も、D(0.62)を超えなかった(0.52)。詳細は 6.10 節と `results/dsrl_smolvla.md`。
- 限界: 評価は 50 エピソード(標準誤差 0.07)。H は 1 回の学習の結果で、学習シードを変えた再現は未実施。
  ゲート(保持の判定)は、シミュレータで調整した閾値に頼っており、実機にそのまま持ち込めるとは限らない。

## 1. 目的と設定

- **目的:** これまでに収集した LIBERO-10 Task 0 のロールアウトデータを活用し、RL Token(論文: arXiv:2604.23073、RLinf の `rlt`)の方法で、凍結した SmolVLA の成功率を上げる。
  評価は、ベースモデルの評価(README のステップ 4)と同じ条件で行う。
- **対象タスク:** LIBERO-10 の Task 0(2 つの物体 — アルファベットスープとトマトソース — をカゴに入れる)。
- **VLA:** `lerobot/smolvla_libero`(約 0.5B)。RL の間、一切更新しない。
- **RL の対象:** VLA が出す行動チャンク(50 ステップのうち先頭 10 ステップを実行)を入力に取る小さな MLP の actor と、twin-Q の critic。
- **実行環境:** RLinf(サブモジュール)に、パッチ `patches/rlinf/smolvla-u-rlt-stage2-libero.patch` を当てて使う。
  GPU は 2 つのコンテナにあり、片方で学習・評価、もう片方で並行実験を行った(結果は共有のファイルシステム経由)。

## 2. RLT のアルゴリズムと実装

### 2.1 アルゴリズム

1. **RL token(Stage 1):** 凍結した VLA の内部特徴(プレフィックスの画像トークンの最終層の隠れ状態、128 トークン × 960 次元)を、
   encoder-decoder(Transformer)で 1 つのトークン(960 次元)に圧縮し、元の特徴を再構成できるように学習する。再構成誤差を損失とする。
   学習後の encoder が、画像から `z_rl`(960 次元)を作る。
2. **actor-critic(Stage 2):** `z_rl`、proprio(8 次元)、VLA の参照行動チャンク(10 × 7)を入力とする。
   - actor: MLP(256×3)。出力は 10 × 7 の行動(tanh)。確率的方策は固定の標準偏差のガウス(`fixed_std`)。
   - critic: 入力は `z_rl` と proprio と行動。twin-Q(2 本、最小値を使う)。
   - 学習: オフポリシー(TD3/SAC 型)。チャンク単位の遷移、割引はチャンクあたり γ^10(γ=0.99)。
     actor の損失は `−q_weight × Q + bc_weight × MSE(actor の行動, 参照行動)`。参照行動のドロップアウト 50%。
     更新の頻度は UTD(新しい遷移 1 件あたりの更新回数)で表し、`update_epoch / train_every_transitions`。
3. **重要局面だけ RL を使う:** 物体を掴む局面(ゲートが開いている間)だけ actor が行動し、それ以外は VLA の参照行動をそのまま実行する。
   リプレイには、ゲートが開いている間の遷移だけを保存する。

### 2.2 RLinf への追加実装(`patches/rlinf/smolvla-u-rlt-stage2-libero.patch`、10 ファイル)

| ファイル | 内容 |

## 3. データと Stage 1(RL token の学習)

### 3.1 特徴量の抽出

- **入力データ:** 再収集した LIBERO-10 Task 0 のロールアウト(`train_v2` の r1〜r4 の各ラウンド)と、評価用(`eval_v2`)、およびデモ(SFT)。
  学習用に 11 セット(r1_m0, r1_m1, r1_m2, r2_m1, r2_m2, r3_m0, r3_m1, r3_m2, r4_m0, r4_m1, r4_m2)、検証用に 3 セット(eval_m0〜m2)。
- **抽出する内容:** 凍結した SmolVLA に、各フレームの 2 枚の画像(agentview と手首)、言語指示、proprio を入れ、プレフィックスの最終層の隠れ状態のうち、
  先頭の画像トークン 128 個(128 × 960)を保存する。
- **フレームの選び方:**
  - 把持が起こる付近(t = 40〜100)は、2 ステップおきに抽出(主)。
  - それ以外のフレーム(2 つ目の局面を含む)は、6 ステップおきに抽出(`feats_rest`)。
  - デモは、183 フレーム(主)と 653 フレーム(それ以外)。
- **量:** 学習用 127,782 フレーム(主)+ 253,215 フレーム(それ以外)= 380,997 フレーム、検証用 6,012 フレーム。
- **並列化:** 抽出は、2 つの GPU(コンテナ)に分けて実行した(再開可能なスクリプト、完了のマーカーファイルつき)。

### 3.2 RL token の学習

- モデル: `RLTTokenTransformer`(2 層、8 ヘッド、埋め込み 960、プレフィックス長 128)。パラメータ 163.5M。
- 入力は、全体の標準偏差 1.1106 で割る(`scale`、チェックポイントに保存)。
- 学習: 6000 ステップ、バッチ 64(うち 10% はデモのフレーム)、AdamW(lr 1e-4、ウォームアップ 200 ステップ、weight decay 0.01)、勾配クリップ 1.0、bf16。約 25 分。
- 結果: 学習 MSE 0.072、検証 MSE **0.0725**(平均を出力するだけの基準は 0.269)。
- 診断(線形回帰): `z_rl` は、手先の位置(R² 0.993)、指の隙間(R² 0.855)、エピソードの成否(正解率 0.925、多数派の基準 0.719)を、よく表す。
  プーリングした生のトークン(960 次元)は、指の隙間 R² 0.948、手先 0.981。
- 成果物: `tmp/rlt_stage1/rlt_stage1_ckpt.pt`(Stage 2 で必須)。

## 4. Stage 2 の設計

### 4.1 重要局面のゲート(把持の判定)

- **把持の確認:** グリッパの指令が「閉じる」(行動の最後の次元 > 0)で、指の隙間が 0.04〜0.071(物体を挟んでいる範囲)にある状態が、**8 ステップ連続**したとき。
- **解除(再武装):** 保持の確認後、指令が「開く」の状態が **3 ステップ連続**したとき、次の局面のために、ゲートを再び有効にする。
- **局面の数:** `num_phases` = 1(1 つ目の把持まで)または 2(2 つ目の把持まで)。
- **`actor_phase` と `pre_actor`(H・I で追加):** 学習する actor が動く局面を指定する(1 = 2 つ目のみ)。`pre_actor=True` のとき、それより前の局面では、
  固定した actor(`rollout.rlt_pre_actor.ckpt_path`)が、評価モード(決定的)で動く。フラグは 2 列(0 列目: 固定した前段 actor、1 列目: 学習する actor)。
- **空振り(I のみ):** 指令が「閉じる」で、隙間が 0.03 以下の状態が 3 ステップ連続したとき、`miss_penalty` を報酬から引く(1 回の空振りにつき 1 回)。

### 4.2 報酬とリプレイ

- **モード:**
  - `grasp_subtask`: 把持が確認されるたびに報酬 +1、最後の局面の把持でエピソードを終了する。段階 1 と、2 局面の学習(F、G、H、I)で使用。
  - `full_task`: 通常の LIBERO のエピソード。報酬はタスクの完了(最初の成功)のみ。`rlt_phase_return` で、局面の最後の遷移に、後から来る報酬(0 または 1)を付ける。C の段階 2 で使用。
- **報酬は 1 回だけ:** LIBERO は、目標を満たしている間、毎ステップ成功を返す。これを毎回報酬にすると、報酬が膨らむ(7 節)。
  環境側で最初の 1 回だけ報酬にした。
- **終端:** `rlt_segment_terminal=True` のとき、各局面の最後の遷移を終端にする(次の行が記録されない場合)。`episode_done` で、本当のエピソードの終わりと区別する。
- **リプレイ:** 容量 50,000、最小 1,000 件。ゲートが開いている間の遷移だけ保存。チェックポイントに、リプレイも含めて保存する(再開用)。

### 4.3 ハイパーパラメータ(最良の H の設定)

| 項目 | 値 |
|---|---|
| 学習用の環境数 | 3(並列。5 では OOM) |
| 環境シード / ノイズシード | 960000 / 960000 |
| エピソード長(学習) | 最大 400 ステップ(評価は 520) |
| 1 回の判断で実行する行動 | 先頭 10 ステップ(50 のチャンクのうち) |
| 1 エポックの内容 | 400 ステップのエピソードを環境ごとに 1 回(約 40〜50 件の遷移が、2 つ目の局面から集まる) |
| エポック数 | 400(約 49 秒/エポック、約 5.5 時間) |
| UTD | 5(`update_epoch=25`、`train_every_transitions=5`) |
| 1 エポックの更新回数の上限 | 400(`max_updates_per_train_step`) |
| バッチ | グローバル 512、マイクロ 128(4 分割) |
| 学習率(actor / critic) | 1e-4 / 1e-4(定数) |
| アルファ(エントロピー係数) | 固定 0(`fixed_alpha`) |
| γ / τ(目標ネットワーク) | 0.99 / 0.005 |
| critic / actor の更新比 | 4 : 1(`critic_actor_ratio=4`) |
| Q の集約 | critic は 2 本の最小値、actor は Q1 |
| 参照行動のドロップアウト | 0.5 |
| `fixed_std`(探索のガウスの標準偏差) | 0.05(F は 0.02) |
| ウォームアップ | 1000 件が集まるまで VLA のみで収集 → 1000 回の更新(BC 重み 7、Q 重み 0.05) → 1000 回で、BC 2.5・Q 0.45 に移行 |
| オンラインの重み | BC 2.5、Q 0.45 |
| RL token | `rlt_stage1_ckpt.pt`(固定) |

RLinf の既定値からの主な変更: UTD 5(既定 `update_epoch=5` → 25)、ウォームアップの長さ(既定 20000/30000 → 1000)、`fixed_std`(モデルの既定 0.002 → 0.02/0.05)、
バッチ 512/128、環境 3、エポック数。

## 5. 評価プロトコル

- ベースモデルの評価(README のステップ 4)と同じ条件: LIBERO-10 Task 0 の **50 の固定初期状態を 1 回ずつ**、最大 520 ステップ、50 ステップのチャンクの先頭 10 ステップを実行、指標は `eval/success_once`。
- RLinf の評価専用モード(`bash evaluations/run_eval.sh libero libero_10_smolvla_rlt_eval ...`)を使用。50 環境ではメモリが足りないため、**2 環境 × 25 パス**で実行(`max_steps_per_rollout_epoch=13000`)。
- 評価シード(`noise_seed`)は VLA の行動のノイズだけを変える。初期状態は同じ。既定は 930000。
- 標準誤差は、n=50 で約 0.07。実験間の差を見るときは、この幅を考慮する。
- 同じ初期状態を揃えた比較(ペア比較): `use_ordered_reset_state_ids=True` で、全ての記録が、同じ順序の初期状態になる(t=0 の位置のずれ 0 で確認)。
- 診断用の記録: `+env.eval.data_collection.*` で、各ステップの状態、行動、成功を記録し、`diag_analyze.py` で集計する。
  - 保持 = 指令が「閉じる」で隙間 0.04〜0.071 が 8 ステップ以上連続
  - 空振り = 指令が「閉じる」で隙間 0.03 以下が 3 ステップ以上連続

## 6. 実験の経過と結果

評価は、断りがなければシード 930000(50 エピソード)。wandb は project `libero_RL`(entity junhand)。

### 6.1 ベースモデル(A、B)

| 評価 | 内容 | 成功率 |
|---|---|---|
| 最初の実験(README) | RLinf の標準経路、`total_num_envs=10` | 0.40(20/50) |
| A | 標準経路、2 環境、シード 930000 | 0.38 |
| **B** | **RLT のコード経路で VLA のみ**(actor を無効化)。以降の比較の基準 | **0.46** |

A と B の差(0.08)は、VLA の行動のノイズの扱いの違いなどで生じ得る。RL の評価は、B と同じ経路を使うため、B を基準にした。

### 6.2 二段階学習(C)

- **段階 1(把持のサブタスク):** 1 つ目の把持が確認されたとき報酬 1、そこでエピソードを終了。250 エポック、`fixed_std=0.02`、UTD 1。
- **段階 2(タスク全体):** 段階 1 の actor・critic の重みから(リプレイは引き継がない)、`full_task` モード、報酬はタスクの完了のみ、150 エポック。1 つ目の把持まで actor が動く。
- 評価(`global_step_400`): **C = 0.60**(success_at_end 0.58)。ベース B の 0.46 から改善。
- 初回の二段階学習(v1)は、報酬の不具合(7 節)で無効になり、v2 で置き換えた。

### 6.3 段階 1 の延長(D)

- 段階 1 のチェックポイント(250 エポック、重みとリプレイ)から、**UTD 5**(`update_epoch=25`)で、500 エポックまで延長した。段階 2(タスク全体の学習)は省略した。
- 評価(`global_step_500`): **D = 0.62**(success_at_end 0.62)。C と同程度で、段階 2 を省いても同じ水準だった。
- 1 つ目の局面だけ RL を使う構成の基準とした。

### 6.4 失敗の診断(B と D)

各ステップの記録から、失敗の種類を集計した。

| | B(VLA のみ) | D(1 つ目だけ RL) |
|---|---|---|
| 成功率 | 0.46 | 0.62 |
| 1 つ目の物体を保持 | 30/50(60%) | 44/50(88%) |
| 1 つ目を保持した後に 2 つ目も保持 | 23/30(77%) | 31/44(70%) |
| 失敗の内訳(掴めない / 1 つのみ / 2 つ以上) | 20 / 6 / 1 | 6 / 11 / 2 |
| 空振り/エピソード | 3.6 | 2.2 |

- RL は、1 つ目の把持を大きく改善する。残る失敗の最大の原因は、**2 つ目の把持に進めないこと**。
- 2 つ目の局面の失敗は、特定の初期状態に固定されず、試行ごとにばらつく(全モデルで必ず失敗する初期状態は 50 件中 3 件のみ)。

### 6.5 2 局面ゲートの学習(E、F、G)

2 つ目の把持も RL の対象にした(`num_phases=2`)。actor・critic は、1 つの重みを 2 つの局面で共有。

- **E(学習なし):** D の actor を、2 つ目の局面にも使って評価 → **0.18**(success_at_end 0.16)。2 つ目を知らない actor が、2 つ目の局面を壊す。
- **F:** D(500)から、2 局面で 250 エポック追加(750 まで、約 4 時間 13 分)。`fixed_std=0.02`、UTD 5。→ **0.52**。
- **G:** F と同じ設定で `fixed_std=0.05`(別の GPU で実行)→ **0.66**。

| | 成功率 | 1 つ目の保持 | 2 つ目への到達 | 空振り/エピソード |
|---|---|---|---|---|
| E | 0.18 | — | — | — |
| F | 0.52 | 46/50 | 29/46(0.63) | 2.1 |
| G | 0.66 | 48/50 | 31/48(0.65) | 1.8 |

2 局面の学習は、2 つ目への到達を改善しなかった(VLA のみ 0.77 に対し、F 0.63、G 0.65)。

### 6.6 critic と RL token の分析

- **critic(F のリプレイ 31,799 遷移: D 由来 13,998、新規の 1 つ目 6,630、新規の 2 つ目 11,171):**
  - 予測と実際の割引つきリターンの関係は、1 つ目で傾き 0.98・相関 0.955、2 つ目で傾き 0.95・相関 0.894。**状態の良さは、よく当たっている**。
  - 行動を変えたときの Q の動き(行動 / 状態)は 0.23(1 つ目)/ 0.26(2 つ目)。critic は行動の違いに反応する。
  - ただし、critic が予測する「actor の行動は参照行動より良い」(+0.056 / +0.057)の、実際の結果への係数は +0.06 / +0.05 で、**ほぼ 0**。
    リプレイには actor の行動しかなく(参照との偏差は RMS 約 0.1)、反事実の結果がないため、検証できない。
- **RL token:** 再構成誤差は、2 つ目の局面(t ≥ 140)で、1 つ目の 1.8 倍。`z_rl` は、局面を線形に 97.5% 識別できる。
- **2 つ目の局面の学習の条件(F・G):** 悪い初期値(E で 0.18)、ウォームアップなしの重み(再開時は BC 2.5・Q 0.45)、
  疎な報酬(2 つ目の保持のみ)、1 つ目と重みの共有。これらが原因かは、確かめていない。

### 6.7 2 つ目の局面の actor を切る評価(F_p1、G_p1)とペア比較

F と G の重みを、1 つ目の局面だけに使い(`num_phases=1`)、2 つ目は VLA に任せて評価した(学習なし)。

| | 成功率 | 1 つ目の保持 | 2 つ目への到達 |
|---|---|---|---|
| F(2 局面とも actor) | 0.52 | 46/50 | 0.63 |
| **F_p1**(1 つ目だけ) | 0.58 | 46/50 | 0.67 |
| G(2 局面とも actor) | 0.66 | 48/50 | 0.65 |
| **G_p1**(1 つ目だけ) | 0.68 | 48/50 | 0.73 |

- 2 つ目の局面の actor を切っても、成功率は下がらず、わずかに上がる方向だった(F +0.06、G +0.02。誤差の範囲)。**共有の 2 つ目の actor は、有益ではない**。
- **ペア比較(同じ初期状態):** 全実験で 1 つ目を保持できた 26 の初期状態に限ると、2 つ目への到達は、B 0.73、D 0.77、F 0.62、F_p1 0.73、G 0.69、G_p1 0.73。
  D の 2 つ目への到達が、見かけ上 0.70 に下がったのは、**選択の偏り**(VLA のみで 1 つ目を保持できるのは簡単な初期状態に偏る)による。
  RL の 1 つ目の局面は、2 つ目を悪くしていない。
- G_p1 は、複数シードの評価で、0.68 / 0.60 / 0.60(平均 0.627)。最初の 0.68 は運の良い評価だった。

### 6.8 2 つ目専用の actor(H、I)

- **設計:** 1 つ目の局面は、**G の actor を固定**(評価モード、決定的)。2 つ目の局面は、**専用の actor と critic を、初期値なしで学習**する(参照行動に BC で合わせるウォームアップ → BC から Q への移行、1 つ目と同じ手順)。
  学習データは 2 つ目の局面の遷移のみ。実装は 4.1 の `actor_phase=1`、`pre_actor=True`、`rollout.rlt_pre_actor.ckpt_path`。
- **H:** 空振りの罰なし。400 エポック(約 5.5 時間)。
- **I:** H に、空振りの罰 −0.2 を追加。別の GPU で実行。
- **検証:** G の重みを、前段と 2 つ目の両方に指定した評価(`G_check`)が、G の 2 局面の評価と全項目一致(成功率 0.66)した。固定した前段 actor の経路は正しい。

| G_p1(1 つ目 G、2 つ目 VLA) | 0.68 | 0.60 | 0.60 | 0.627 | 102/139(0.73) |
| **H(2 つ目専用 actor)** | **0.74** | **0.70** | **0.70** | **0.713** | **113/139(0.81)** |
| I(H + 空振りの罰) | 0.68 | — | — | — | 34/48(0.71) |

- H は、3 つの評価シードのすべてで、G_p1 より成功率が高く、2 つ目への到達も多い(+3、+4、+4 件)。1 つ目の局面は同じ G なので、**差は 2 つ目の局面だけで生じている**。
- ただし、合計の差(成功率 +0.09、2 つ目への到達 +0.08)は、標準誤差の約 1.6 倍。評価の 3 回は、同じ 50 の初期状態を、シードだけ変えたもので、独立ではない。

- 空振りは、1 エピソードあたり、ベース 3.6 → H 1.6。

### 6.10 ベースの複数シード評価と、追加の検討(DSRL、時間オフセット報酬)

**ベース(VLA のみ)を、評価シード 5 つで評価した。** RLT の経路で actor を無効にし、50 の固定初期状態を 1 回ずつ、2 環境 × 25 パス。

| 評価シード | 930000 | 941000 | 942000 | 943000 | 944000 | 平均 |
|---|---|---|---|---|---|---|
| 成功率 | 0.46 | 0.44 | 0.34 | 0.42 | 0.48 | **0.428**(シード間の標準偏差 0.054) |
| 1 つ目の保持 | 0.60 | 0.56 | 0.58 | 0.54 | 0.62 | 0.580 |

- 初期状態ごとの、5 回中の成功回数(状態の数): 0 回 17、1 回 4、2 回 8、3 回 6、4 回 6、5 回 9。**毎回成功 9、1 度も成功しない 17、ときどき成功 24。**
- 1 度でも成功した状態の件数は、k 個のシードで、21.4(k=1)、27.6、30.6、32.2、33(k=5)と頭打ちで、Chao1 推定でも、あと約 1 件(合計 約 34 件)。
  **ノイズ(評価シード)を理想的に選べた場合の上限は、成功 約 34 件(0.68)** で、H(3 回の平均 0.713)と同程度。
- ある評価シードで失敗した状態(26〜33 件)のうち、ほかのシードで成功した件数は 9〜16 件。1 度も成功しない 17 件は、どの評価シードでも一定。
- ベースが 5 回とも失敗した 17 状態のうち、RLT で成功した件数: G_p1 12、H 11 / 10 / 8(評価シード 930000 / 931000 / 932000)。ノイズを変えるだけでは、届かない状態を、RLT が成功させている。

**DSRL(SmolVLA 版、詳細は `results/dsrl_smolvla.md`)。** RL token + proprio から、凍結した SmolVLA の初期ノイズ(先頭 10 ステップ × 32 次元)を出す SAC の actor を、
D と同じ設定(1 つ目の把持のサブタスク、500 エポック、UTD 5、約 83,000 回の更新、17,680 遷移)で学習した。

| | ベース | **DSRL** | D | H |
|---|---|---|---|---|
| 成功率(シード 930000) | 0.46 | **0.42 / 0.52**(2 回の評価。平均 0.47) | 0.62 | 0.74 |
| 1 つ目の保持 | 30/50 | 36/50 | 44/50 | 48/50 |
| ベースが失敗した 27 状態のうち、成功 | — | 8 | 14 | 18 |
| ベースが 1 つ目を保持できなかった 20 状態のうち、保持 | — | 7 | 16 | 18 |

- 事前の診断: ノイズ(標準偏差 1)で、行動チャンクが変わる量は、xyz で 1 ステップあたり 0.013〜0.019(RLT の補正は約 0.1 の約 1/5〜1/8)。ノイズを 2 倍にすると約 4 倍(0.053〜0.063)、
  3 倍以上では、VLA の分布から外れ始め、4 倍で壊れる(範囲外 約 9.5%)。
- 結果: DSRL は、1 つ目の保持を約 6 件(60% → 72%)改善するだけで、RLT(D 88%、H 96%)に届かない。critic の `q_pi` は、学習を通じて、ほぼ変わらなかった(0.435 → 0.412)。
  評価は、ノイズをサンプリングするため、同じ重みでも、評価ごとに変わる(0.42、0.52)。
- 限界: 設定は 1 つだけ(`dsrl_mean_max=1.5`、`fixed_std=1.0`、BC の重み 0.05)。RLinf の元の設定(16 環境、`update_epoch` 200)とは、データ量・更新量が違う。

**時間オフセットを報酬に足す方法(E2b)。** 2 つの RL token から、その間に進んだ時間を予測する小さな MLP(別環境で学習)の出力を、把持の報酬 +1 に加算
(`reward_mode=add`、`reward_scale=2.5`)。D と同じ設定(500 エポック、3 環境、UTD 5)で学習した。

| | success_once | success_at_end |
|---|---|---|
| **E2b(把持の +1 + オフセット)** | **0.52**(26/50) | 0.52 |
| D(把持の +1 のみ) | 0.62 | 0.62 |
| ベース(VLA のみ) | 0.46 | 0.44 |

- 学習中の rollout の成功率は、最初の 50 エポックの平均 0.567 → 最後の 50 エポックの平均 0.727。評価では、D を超えなかった(差 −0.10。標準誤差の約 1.4 倍で、悪化とは断定できない)。
- 参考(別環境の結果、依頼書より): オフセットだけを報酬にした場合(把持の +1 なし)は 0.26(E1-B)、critic なしのフィルタ付き SFT は 0.32(E1-A)。把持の +1 を残す限り、ベースを下回らなかった。
- E2b の学習・評価データは、その後、削除された。

## 7. 発生した問題と修正

1. **報酬が毎ステップ繰り返される(最初の二段階学習 v1 が無効):** LIBERO は成功した後も毎ステップ成功を返し、遷移あたりの暗黙の報酬が約 250 になった(critic の損失 2382 → 39)。
   環境で報酬を 1 回にし、`rlt_phase_return` の後続報酬を 0 または 1 に制限した。修正後の暗黙の報酬は 1.000 を確認。v2 で置き換えた。
2. **リプレイの変換で、最初の `done` の後を捨てていた:** 2 つ目の局面が失われた。`episode_done` を導入し、本当のエピソードの終わりと、局面の区切りを区別した。
3. **メモリ上限(cgroup 25GB):** 学習用の環境は 3 つで約 20〜21GB。5 環境の評価は OOM になり、2 環境に変更。
4. **再開時の相対パス:** チェックポイントのパスが、学習の作業ディレクトリで解決できず、再試行が 3 回無駄になった。絶対パスに修正。
5. **Hydra の struct モード:** YAML にないキーは、`+` なしでは指定できない(新しい設定値は YAML に追加した)。
6. **評価ログの上書き:** C の評価ログが、D の評価で上書きされた。C の値(0.60)は wandb から復元した。
7. **アップロードスクリプトの実行環境:** システムの python では、`wandb` が使えない(`tmp/rlt_stage2/wandb/` が、同名のパッケージとして干渉する)。仮想環境の python で実行する。
8. **プロセスの停止:** `pkill -f` は、自分のシェルに一致して落ちる。PID を指定して停止する(CLAUDE.md に禁止事項として記載)。

## 8. 考察と限界

- **改善の源泉:** 成功率の改善の大半は、1 つ目の把持の改善による(保持 60% → 93〜96%)。
  ベースの VLA は、1 つ目の物体を掴めずに終わる試行が 40% あり、RL の小さな補正(参照行動からの RMS 約 0.1 の偏差)が、これを減らした。
  補正のどの部分が効いたか(掴む位置、タイミングなど)は、調べていない。
- **2 つ目の局面:** 共有の actor で学習すると、改善しない(悪化)。専用の actor を、VLA 相当の初期値から、固定した 1 つ目の actor とあわせて学習すると、VLA をわずかに上回る(0.81 対 0.77)。
  ただし、critic の「行動の良し悪し」の予測が、結果で確認できていないため、改善の理由は確定していない。
- **限界:**
  - 評価は 50 エピソード(標準誤差 0.07)。H の評価は 3 回(同じ初期状態)。ベースの評価は、ほぼ 1 回(最初の実験 0.40、同じ経路 0.46)。
  - H は、1 回の学習の結果。学習シードを変えた再現は、未実施。
  - 単一のタスク(Task 0)のみ。
  - ゲートの閾値(隙間 0.04〜0.071、8 ステップ、解除 3 ステップ、空振り 0.03)は、シミュレータで調整したもの。実機では、グリッパ幅のノイズ、キャリブレーション、物体の違いで、再調整が要る。
    また、2 局面のゲートは、保持の回数を数える状態(履歴)を、ロールアウト側に持たせる必要がある。1 局面(1 つ目だけ)なら、ゲートは最初の保持の 1 回の判定で済む。
- **DSRL・時間オフセット報酬:** どちらも、RLT の補正方式(D・H)を超えなかった(6.10 節)。ノイズで動かせる量が小さく(1 ステップあたり 0.013〜0.019)、理想的なノイズ選択の上限も、H と同程度(成功 約 34 件)と見積もられたため、DSRL に、大きな改善の見込みは低いと見ている。
- **未実施:** H の学習シードの再現、エポックの延長、RL token の再学習(2 つ目の局面のフレームを密にする)、critic の信頼性の改善(アンサンブルなど)。

## 10. ベースモデルと最良の結果の比較

同じ評価シード(930000)、同じ条件(Task 0、50 の固定初期状態、最大 520 ステップ)。

| 指標 | ベース(最初の実験、RL なし) | ベース(同じ経路で再評価) | 最良(H、最良の評価) |
|---|---|---|---|
| **成功率** | **0.40**(20/50) | 0.46(23/50) | **0.74**(37/50) |
| 1 つ目の物体を保持できた割合 | — | 60%(30/50) | **96%**(48/50) |
| 保持後に、2 つ目も保持できた割合 | — | 77%(23/30) | 79%(38/48) |
| 空振りの回数/エピソード | — | 3.6 | **1.7** |
| 失敗したエピソード数 | 30 | 27 | **13** |
