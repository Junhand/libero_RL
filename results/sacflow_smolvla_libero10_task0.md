# SAC Flow を smolVLA の action expert に適用する試み(LIBERO-10 Task 0)

2026-10-06 実施。1 回の試行(p3)の結果であり、結論は「ベースと有意差なし」。

## 実装
- スクリプト: `scripts/sacflow/sacflow.py`(p3)、`sacflow_p2.py`(崩壊した p2)、`run_p3.sh`(起動)。単一プロセスの試作で、RLinf 本体は変更していない。
- 学習対象: action expert(約 99M パラメータ。float32 + bf16 autocast)。VLM は凍結し、prefix は no_grad。
- 方策: K=10 のノイズ付き Euler(ロールアウト σ=0.02、学習 σ=0.05)を勾配つきで通す(SAC Flow の Flow-G/T に相当)。
- critic: [VLM 特徴(1920) + 行動チャンク(70)] → MLP 2 本(最小値)、EMA ターゲット(τ=0.01、γ=0.99)。
- データ: Task 0 の固定 50 初期状態、3 環境、成功で報酬 1、チャンク単位の遷移、uint8 画像のエピソードバッファ(50 エピソード = 約 9GB)。

## 設計の経緯
| 版 | 設計 | 結果 |
|---|---|---|
| p1 | (初版) | ディスク quota 超過で消失(原因は容量。設計の評価はできず) |
| p2 | Q を最大化 + 参照への BC(α=2.5)、actor lr 1e-5、critic のウォームアップ 36 エピソード | actor 更新開始後に学習中の成功率が 0.33 → 0.07 → 0(約 1.3 時間で停止)。方策が崩壊 |
| p3 | 下記 | 崩壊せず完走 |

p3 の変更点:
- 参照(初期 expert)の出力と、同じノイズで比較する BC(`bc_weight=1.0`)。
- Q の勾配を平均 |dQ/da| で正規化(λ = q_weight / mean|dQ/da|、q_weight=0.06)。生の dQ/da は要素あたり約 1e-3 と小さく、λ=1 では実質無効だった。
- drift(参照との RMS 差)が 0.1 を超えたら Q の項を切るガード。
- actor lr 2e-6、critic のウォームアップ 150 エピソード(バッファは 50 のため直近 50 を使用)、成功率の崩壊(30 エピソード平均 < 0.12 が 8 イテレーション)で自動停止。
- 初回起動は buf_eps=160 でメモリ上限(約 25GB)を超える見込みのため、buf_eps=50 にして再起動した。

## p3 の実行結果
- 17:30〜21:08(3.6 時間)、166 イテレーション、500 エピソード、環境ステップ約 5.2 万。exit=0、自動停止なし。
- 更新回数: actor 1,872 回、critic 約 2,700 回(1 イテレーションあたり 16 回、バッチ 16)。
- 時間内訳: ロールアウト 2.7 時間(74%)、更新 0.94 時間(26%)。actor 更新 1 回あたり約 1.5 秒。
- actor 更新中の平均: drift 0.062、ガード通過率 0.91、dQ/da 0.0008、λ 約 80、BC 0.33、critic 損失 0.003。
- 学習中の成功率(ノイズ付き、直近 30 エピソード平均): ウォームアップ(方策は初期のまま)平均 0.36、最後の 40 イテレーション平均 0.43。誤差は約 ±0.09 で、有意ではない。

## RL Token との比較
| | SAC Flow p3 | RL Token(E1/D 設定) |
|---|---|---|
| 学習時間 | 約 3.6 時間 | 約 4.2 時間 |
| 更新回数 | actor 1,872 回 | 約 8.5 万回(概算。`update_epoch=25`、約 34 遷移/エポック、500 エポックからの推定で、実測ではない) |
| バッチ | 16 | 512 |
| 1 回あたり | 約 1.5 秒 | 約 0.1 秒 |
| 学習対象 | expert 約 99M | actor 約 5 MB |

更新回数に差が出る理由: (1) UTD が違う(RLT は 5、p3 は約 0.8)、(2) K=10 の逆伝播と VLM prefix のため 1 回が約 15〜50 倍重い、(3) メモリのためバッチを 16 までしか増やせない。同じ約 8.5 万回を行うと約 35 時間かかる。

## 解釈と注意
- 崩壊はしなかったが、改善も確認できなかった。「壊さずに動かせること」までの確認。
- 原因は、(a) 更新回数が少ない、(b) actor を参照に強く縛った設計(平衡時の drift 約 0.03)のどちらか、または両方。1 回の試行では切り分けられない。
- p3 の評価は 1 回(シード 930000)のみ。学習時のロールアウトは σ=0.02 のノイズ付きで、評価はノイズなし。
- ディスク quota 超過により p1 が消えた。wandb の run(`sacflow_smolvla_p3`)の他に、smoke、smoke2、p1、p2 の不要な run が残っている。
